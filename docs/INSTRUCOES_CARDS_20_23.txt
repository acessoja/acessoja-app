5. REPETIR NO WINDOWS / NAVEGADOR

Em frontend, use o SDK 3.47.4 configurado no projeto (FVM quando instalado):

  fvm flutter pub get
  fvm flutter gen-l10n
  fvm flutter analyze
  fvm flutter test
  fvm flutter build web
  fvm flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8000

Sem FVM, os mesmos comandos com flutter funcionam quando essa versão do SDK está
no PATH. Os comandos de validação repetidos no ambiente podem usar --no-pub após
pub get bem-sucedido. Para execução local via servidor web, se Chrome não for
iniciado automaticamente:

  fvm flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8080 --dart-define=API_BASE_URL=http://localhost:8000

Abra a URL informada pelo comando no navegador. Execute o backend de
desenvolvimento em outra janela, com o ambiente/configuração de CORS já previstos
no projeto. Em outro computador, localhost deve ser substituído pelo endereço
real do backend; não coloque credenciais nas preferências de leitura.

O uso no navegador não exige Android SDK. O build Android é uma verificação
separada para um ambiente com SDK/JDK 17:

  fvm flutter build apk --debug

Backend, na raiz, em banco de teste isolado:

  python manage.py check
  python manage.py makemigrations --check --dry-run
  python manage.py migrate
  python manage.py spectacular --fail-on-warn
  flake8 . --max-line-length=120 --exclude=migrations,__pycache__,.venv,venv --statistics --count
  pytest --cov=. --cov-report=term-missing --cov-report=xml:coverage.xml --cov-fail-under=80 -v

PostgreSQL 16, com DATABASE_URL de teste e configuração do job do workflow:

  pytest -q contribuicoes -k postgresql_concurrent

Os quatro testes precisam executar sem skips para validar concorrência real.
Relatórios, bancos e caches produzidos pelos comandos não pertencem ao ZIP.
